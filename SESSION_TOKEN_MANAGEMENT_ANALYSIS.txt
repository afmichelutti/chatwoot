# CHATWOOT SESSION AND TOKEN MANAGEMENT ANALYSIS

## SUMMARY

Chatwoot uses DeviseTokenAuth for authentication combined with Redis-based presence tracking and ActionCable WebSockets. The online/offline alternation issue likely stems from multiple sessions, stale Redis presence data, or WebSocket connection conflicts.

## CRITICAL COMPONENTS

1. AUTHENTICATION TOKENS
   - Access Token (users.tokens) - Managed by DeviseTokenAuth
   - Pubsub Token (users.pubsub_token) - For WebSocket authentication
   - Access API Token (access_tokens table) - Personal API tokens

2. AVAILABILITY TRACKING
   - Database: account_users.availability (0=online, 1=offline, 2=busy)
   - Redis Hash: ONLINE_STATUS::{account_id} -> {user_id: status}
   - Redis Sorted Set: ONLINE_PRESENCE::{account_id}::{USERS|CONTACTS} -> timestamp

3. PRESENCE DURATION
   - Default: 20 seconds (configurable via ENV['PRESENCE_DURATION'])
   - After 20 seconds without update, user appears offline

## ROOT CAUSES OF ALTERNATING STATUS

1. Pubsub token NOT regenerated on login/logout
   - File: app/models/concerns/pubsubable.rb
   - Token only rotates on password change
   - Old WebSocket connection may still be active
   - New login with same token creates confusion

2. Redis presence expires every 20 seconds
   - File: lib/online_status_tracker.rb
   - If user idle >20 seconds, appears offline
   - Next presence update makes them online again

3. Multiple sources of truth for availability
   - Database availability column
   - Redis status hash
   - Redis presence sorted set
   - These can get out of sync

4. Logout doesn't invalidate WebSocket tokens
   - Old connection still updates Redis
   - Stale data persists after logout

## REDIS STRUCTURE

ONLINE_STATUS::{account_id} = Hash
  Field: user_id
  Value: "online" | "offline" | "busy"
  Set by: OnlineStatusTracker.set_status
  Get by: OnlineStatusTracker.get_status

ONLINE_PRESENCE::{account_id}::USERS = Sorted Set
  Score: Unix timestamp (time of last update)
  Member: user_id
  Set by: OnlineStatusTracker.update_presence
  Get by: OnlineStatusTracker.get_presence

ONLINE_PRESENCE::{account_id}::CONTACTS = Sorted Set
  Same structure as above but for contacts

## WHY TOKEN REGENERATION HELPS

When reset_access_token is called:
1. Invalidates old access_token (personal API key)
2. Generates new token
3. May trigger frontend to re-authenticate
4. Could cause WebSocket reconnection
5. New connection = new presence tracking

However, does NOT:
- Regenerate pubsub_token
- Kill old WebSocket connections
- Clear old Redis entries
- Invalidate devise tokens in users.tokens

## CONFIGURATION AFFECTING BEHAVIOR

devise_token_auth.rb:
- change_headers_on_each_request = false
  * Token doesn't change after each request
- token_lifespan = 2 months
  * Long lived tokens
- remove_tokens_after_password_reset = true
  * Old tokens cleared on password change
- max_number_of_devices = 25
  * Up to 25 concurrent devices allowed

Online Status Tracker:
- PRESENCE_DURATION = 20 seconds (env configurable)
  * User appears offline after 20s inactivity

Profiles Controller:
- auto_offline parameter on availability endpoint
  * Boolean flag for auto-offline feature
