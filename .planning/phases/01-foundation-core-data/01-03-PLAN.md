Analyze the two permission approaches in the merged codebase and document a decision.

**Step 1: Read the merged conversations_controller.rb**

Examine the final state of `app/controllers/api/v1/accounts/conversations_controller.rb` to understand how both approaches coexist after the merge.

**Step 2: Read the upstream ConversationPolicy**

Check `app/policies/conversation_policy.rb` to understand what the upstream `authorize @conversation, :show?` actually checks.

**Step 3: Read our PermissionFilterService**

Find and read any custom `PermissionFilterService` or similar service that we added for conversation filtering. Check:
```bash
grep -rn "PermissionFilter" app/
```

**Step 4: Evaluate the approaches**

| Approach | Covers | Gaps |
|----------|--------|------|
| Upstream Pundit `authorize @conversation, :show?` | Single conversation access (show, update, destroy actions) | Does NOT filter collection endpoints (index, search) — only checks after a conversation is loaded |
| Custom PermissionFilterService | Collection filtering (index, search, filter endpoints) | May not cover single-resource authorization |
| Both (complementary) | Complete coverage — Pundit for single resources, filter service for collections | Slight complexity increase, but maximum security |

**Step 5: Record the decision**

The recommended approach is **Both (complementary)** because:
- Pundit `authorize @conversation, :show?` catches unauthorized access to individual conversations (direct URL, API call)
- PermissionFilterService catches data leakage in collection endpoints (search, filter, contact history)
- Defense in depth — even if one fails, the other provides protection
- Phase 2 (Security Audit) will unify the implementation pattern

Update `.planning/PROJECT.md` in the Key Decisions table:
- Change the "Evaluate upstream permission fix vs custom PermissionFilterService" row
- Set Outcome to the decided approach with rationale

Update `.planning/STATE.md`:
- In the Decisions section, change the "Permission approach (PENDING)" entry to resolved
- Remove the concern about "Permission approach divergence must be resolved before Phase 2 begins"

**Step 6: Commit the decision**

Decision: Keep BOTH upstream Pundit authorize and custom PermissionFilterService.
- Pundit authorize: single-resource access control (show, update, destroy)

- Complementary approach provides defense-in-depth
